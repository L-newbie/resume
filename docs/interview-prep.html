自我介绍

面试第一分钟 · 一段话，直接照着读
目标时长 约 60 秒
SPEECH · 完整讲稿（第一视角，整段连读）
  1. 开场 · 一段话全文「面试官您好，我是赫卫东，很高兴参加今天的面试。过去七年我一直在做数据开发相关的工作：早期主要处理各类不规范的文本数据和数据库，把它们整合成可分析、可检索的结构化数据，这段经历帮我打下了数据治理的基本功。2021 年底到现在，我在地平线负责支持算法和模型迭代的数据工作，覆盖从原始数据解析、目标数据挖掘、真值数据的标注管理，到模型输入数据的结构化打包、验证及发版的完整链路，同时负责数据 DAG 云端和本地链路的工具开发，让这条链路更自动化、更可复用。以上是我的基本情况，谢谢。」
⚠ 收口后停住，把话头交给面试官。不要主动展开任何项目细节——每个块被追问时都有后面几页的准备。
时长控制：全段约 210 字，正常面试语速下 50–60 秒。面试官示意「简单介绍一下」时，可从「2021 年底到现在」起读、砍掉早期经历那一句，压到 30 秒左右。
01 · PROJECT · CORE

动态感知数据闭环

地平线 · 2024.03–2024.10 · 最重要的项目，讲 3–4 分钟
面试官问「讲一个你最有代表性的项目」→ 就讲这个
标签与检索统一语义底座
→
数据挖掘批量推理筛选场景
→
数据标注预标注 + 人工 + 质检
→
数据打包LMDB 训练集出口

1四个环节 · 逐个口述

① 标签与检索 先讲语义底座，注意讲清「公司级 → 我负责的部分」的层级

  1. 公司级结构「整个项目从标签讲起，因为它是检索和后续所有环节的语义底座。公司的标签树按来源分成项目标签、标签库、地理场景、采集标签、路测标签等若干子树，各来源的标签统一挂载在时间线标签体系上，可以跨来源组合检索。」
  2. 我负责的部分「我负责其中动态障碍物场景库的标签树设计——围绕目标类型、动静态属性、运动状态这些维度，把『何种路况构成同一类场景』的判断标准化成层级化的可执行规范。」
  3. 自动 tagger「在规范之上，我开发并长期维护动态障碍物方向下的自动 tagger——基于路采数据回传信号里的结构化字段（工况、位姿、目标框等），实现标签的规则化批量推断与挂载；标签回写标签树数据库，和工况环境等其他来源的标签形成关联。」
  4. 前端检索「检索侧，用户在 web 端点选按钮组合标签条件，也可以直接编写 SQL 完成数据获取。这两条路径我主导提供数据支撑，并完成各类场景的检索测试——高频组合和长尾边界组合逐类验证准确性与召回边界，保证算法团队拿到的结果直接可用。」

② 数据挖掘 链路化，不是一次性脚本

  1. 主链路「标签把数据组织起来之后，下一步是把需要的数据从海量路采里挖出来。我开发了数据挖掘链路：检测模型对路采数据执行批量推理，按工况、目标类型、置信度阈值等条件组合筛选候选场景，命中的结果沉淀为可检索的结构化数据——是链路化的持续产出，不是一次性脚本。」
  2. 多模态补充「检测模型只认『框得住的目标』，所以我引入多模态模型补充语义级挖掘——它能理解『什么场合下出现的什么目标』。两者互补，可挖掘场景的覆盖面显著扩大。」
  3. 集群调度「挖掘执行依托云端集群批量调度，推理任务按数据批次组织，支持断点续跑和结果增量合并，保障大规模路采数据下的挖掘吞吐。」
  4. 属性随行「挖掘结果在链路中携带工况、目标类型等属性信息，随数据一并进入下游标注与打包环节，支撑后续按场景筛选与统计——不依赖平台级的自动联动机制，环节衔接靠数据本身带属性。」

③ 数据标注 讲成本结构，不是流程复读

  1. 两级筛选「挖出来的数据不直接送标，先做两级筛选：自动粗筛按模型置信度、目标密度、场景覆盖等指标对候选数据分级，把明显低价值的先过滤掉；粗筛结果再由人工二次精筛，确定最终入标范围——核心是不让标注预算平均摊派。」
  2. 预标注「执行上用预标注——检测模型的推理结果作为标注初稿，人在上面校正而不是从零绘制，降低单帧标注成本；预标注质量与人工校正量按批次统计，反向用于调整预标注模型和阈值。」
  3. 规则文档 + 质检「同时制定标注规则文档统一判定口径——目标类型边界、遮挡截断怎么处理、歧义场景怎么裁决，都写清楚；标注完成后执行质检和抽检，保障真值质量可核查。」

④ 数据打包 重点环节，多停留

  1. 定位「打包是训练前的最后一站，也是我对这个项目最有信心的部分。」
  2. 打包内容「我负责把标注产出的真值结果打包成 LMDB 格式的训练集——内容包括标注结果、数据索引、图像数据、位置信息等，整体符合模型训练的输入结构。」
  3. 工程化流程「打包流程做了工程化：以数据批次为单位组织打包任务，支持增量打包与版本化管理——历史训练集可复现、可回溯到具体批次与切片。」
  4. 配置化定制「打包遵循既定的通用规则，在此之上按专题定制内容——样本组织方式、数据范围、版本标识——定制不侵入通用流程，新专题打包只需要调整配置。」
  5. 内建验证「打包过程还内建了数据验证：完整性校验保证样本数和真值记录一一对应，格式校验保证训练框架直接可解析，统计核对类别分布——异常批次在进训练之前就被拦截。」

2项目总结 · 口述收尾

  1. 价值在哪「这个项目的价值不在任何单点工具，而在四个环节以统一规范衔接之后，整条链路的可复用性。」
  2. 转变「数据供给从『按人力排期』变成了『按需求配置』。」
  3. 个人意义「对我个人而言，它是我真正理解『数据基础设施』的地方——杠杆从来不在某个精巧的脚本，而在于让整条链路不需要人推着走。」
02 · PROJECT · METHODOLOGY

小动物目标检测专题

地平线 · 2024.05–2024.10 · 长尾方法论的最佳素材，讲 2–3 分钟
适合被问「你解决过最难的数据问题」时使用
SPEECH · 背景 + 问题本质
  1. 类别特性「这个专题是个典型的长尾问题。猫狗在路面出现频率极低，但一旦漏检导致碾压、或误检触发幽灵刹车，安全后果和舆论代价都很严重——典型的『安全相关但样本极稀』。」
  2. 难点在低频本身「难点就在低频本身：海量路采数据里这类目标是稀疏信号，全量送标成本不可接受，随机抽样又几乎命中不了正样本。」
  3. 解法定位「解法不在模型侧，在数据侧：怎么在成本约束下，把稀疏正样本从海量数据里富集出来。」

1三级漏斗 · 核心口述

设计原则一句话先说：「递进式成本分配——每一级的单位成本递增、精度递增，处理量递减一个数量级。让最贵的手段只作用于最小的数据量。」
一级 · 规则粗筛先验压缩数量级 · 成本≈0
→
二级 · 模型精提语义级判断 · 单帧贵但集合已小
→
三级 · 规则化人审人工终审 · 量最小 · 纯度最高
  • 一级 · 讲「先验」并主动讲它的缺陷。「联合内部工况标签、时间窗口，加上猫狗高发区域的先验分布——住宅区周边、城市道路夜间。候选集从 PB 级压到可处理量级。成本趋近零，但代价是召回有限——先验之外的出现场景这一级会漏，需要后续迭代补先验。」
    ⚠ 主动承认缺陷：面试官听到「我知道这级会漏什么」时，对你方法论成熟度的判断会上一个台阶。
  • 二级 · 讲「从时间地点像 → 画面内容像」。「引入开源大模型对粗筛候选做语义级判断，保留真正可能包含目标的帧并给置信度。单帧成本显著高于规则，但作用在已压缩的集合上，总成本可控。」
  • 三级 · 讲「规则化」三个字。「制定明确的判定规则文档——目标可见性、遮挡比例、最小尺寸下限——然后人工终审。人只做规则内的裁决，不做主观发挥。」

2数据运营 · 第二层内容（追问再讲）

  • 漏斗阈值迭代。精提模型对不同类别判分可靠度不同——按筛选反馈统计各类误检漏检，逐类调阈值，不全局一刀切。
  • 标注规范治理。修订规则文档，明确遮挡、模糊、远距离小目标的判据，压缩标注员主观裁量空间。
  • 质量闭环。协调标注资源、全程监控质量，回流数据直接可训练，不返工。
  • 需求池建设。沉淀标准格式数据 + 覆盖不同时间跨度与场景类型的需求池，后续迭代按需取数，不从头重挖。

3收尾口述

  1. 直接交付「这个专题交付了可直接训练的正样本数据集，支撑检测能力迭代上线。」
  2. 方法论沉淀「但更重要的产出是固化下来的长尾方法论：稀疏目标的关键不在标注更多，而在筛选更准。」
  3. 被复用「『粗筛→模型精提→规则人审』这个结构后来被多个专题直接复用，成了团队处理低频类别的标准范式。」
03 · PROJECT · ENGINEERING

锥桶数据挖掘

地平线 · 2025.08–2026.01 · 展示工程化与大模型落地能力，讲 2–3 分钟
适合被问「怎么把大模型用进生产链路」时使用
SPEECH · 背景
  1. 语义「锥桶承载的是施工区语义——它标记的不是一个障碍物，而是『这条车道此刻不能走』，属于漏检代价高、场景差异大的类别。」
  2. 组合爆炸「难点是组合爆炸：高速养护、城区占道、事故现场、临时管制，各自的锥桶排布、密度、光照背景完全不同，单一规则或单一模型都覆盖不全。」
  3. 数据侧的问题「数据侧要回答：怎么让一条链路同时消化差异这么大的场景，还能按需扩展。」

1三个讲点

① DAG 编排 先讲结构

  1. 节点拆分「整条链路拆成职责单一的任务节点——挖掘、匹配、验证、导出——以 DAG 声明依赖后执行。」
  2. 容错「节点间数据落盘、状态可查，某一环失败只重跑该节点，不必从头再来。」
  3. 并行吞吐「节点按场景类型分组并行，不同场景的挖掘互不阻塞，整体吞吐不被最慢场景拖累。」
  4. 算力分配「算力按节点特性分：规则筛选和 IO 密集的走 CPU，模型推理排 GPU 队列。」

② 场景解耦 回答「组合爆炸」

  1. 独立参数「每个场景类型各自维护独立的筛选条件和判定参数。」
  2. 互不干扰「调整高速养护的规则，不影响进行中的城区占道任务。差异极大的场景得以在同一条链路上独立演进。」
  3. 点题「这就是『消化差异』的答案：不是做一个大而全的规则，而是让差异活在配置里。」

③ 多模型分工 回答「按需扩展」

  1. 分层接入「接入 Qwen-VL、SAM3、YOLOv8 并按能力分层：视觉语言模型做场景级语义判断——是否施工区、什么排布类型；检测模型做实例级定位和计数；分割模型补轮廓精度。」
  2. 提示词固化「提示词逐项对照测试——同一场景不同表述提问、比较判分稳定性——稳定复现的组合固化成 config。换模型升级变成改配置，不是改代码。」

2收尾口述

  1. 直接结果「链路跑通后，多场景锥桶数据供给进入稳定节奏——每个训练与发版周期稳定满足 10w+ 的数据需求。」
  2. 扩展方式变了「更关键的是扩展方式变了：新增一类锥桶场景不再是写一套新脚本，而是加一个任务节点、补一段 config。」
  3. 呼应前文「之前专题沉淀的『配置化接入』在这里又验证了一次——这套东西是能生长的。」
04 · PROJECT · AI-NATIVE

Agent Skill 知识服务化

地平线 · 2026.06–2026.09 · 最近的 AI 应用落地，讲 2 分钟
适合被问「AI 时代数据团队怎么提效」时使用
SPEECH · 背景 + 方案
  1. 问题「数据生产链路的知识——流程步骤、参数怎么填、不同项目类型的阈值差异——散落在文档、脚本注释和少数人的记忆里。文档是静态的，读者还得自己判断『我的场景该用哪组参数』。瓶颈不在缺文档，在知识无法被随时、准确地检索到。」
  2. 第一层 · 知识沉淀「把全流程知识整理成一套 Agent Skill——能力概览、快速路由表、速查卡、参考文档四层结构，把用户意图直接映射到对应内容。每个条目都落到可直接复制运行的命令和参数。特别重要的一点是显式声明越界情形——宁答『不在范围内』，不编造任何 ID、路径或命令。」
  3. 第二层 · 服务化「封装成容器化问答服务常驻集群，接进协作工具监听群消息，先回执确认再异步生成答案，会话 ID 维持多轮追问，回复渲染成平台原生卡片、命令直接可复制。」
  4. 可靠性「子会话被约束为只能依据 Skill 文档作答——从机制上杜绝编造。」

1收尾口述

  1. 结果「知识从『问人』变成『问服务』：团队在群里提问就能拿到带命令和参数的可执行答案。」
  2. 验证了什么「这个项目验证了一条路径——个人经验可以系统性地转化为团队随时可调用的工程资产，载体是一个能自己跑下去的服务，不需要专人维护。」

2讲这个项目的加分点

  • 「可靠地说不知道」是整个设计的眼。面试官听过太多人吹大模型能力，很少见到有人把「越界即拒答」设计进机制。主动讲这一点，直接区分你和其他把 AI 挂嘴边的候选人。
  • 三个工程决策值得点出：
    • 容器化交付 —— 消除环境差异
    • 集群常驻 —— 可用性不依赖任何个人终端
    • 数据挂载全部只读 —— 服务只需读取，写权限只会放大误操作后果
    这三个都是「基础设施思维」的证据。
05 · EXPERIENCE · ROOTS

电诈资金流向分析

集侦云 · 2021.03–2021.06 · 讲 2 分钟
被问「最有成就感 / 最早期的代表性工作」时使用
SPEECH · 背景
  1. 案情「一起以网络赌博为外壳的跨境电信诈骗案。资金从受害人充值进来之后，经过多层线上转账和线下取现反复拆分，最后流向境外。」
  2. 数据现状「原始材料是几十张字段口径互不一致的 Excel 和 SQL 表——账户、自然人、企业、交易流水相互交织。」
  3. 常规做法的问题「这类案件的常规做法是把全部关联投射成一张关系图，但那只能得到一张没法解读的稠密网络。」
  4. 真正需要什么「侦查需要的不是拓扑图，是几个可以立即去核查的具体账户。」

1四个方法步骤

  • ① 异构账表治理。几十张表分属赌资流水、银行明细、第三方支付——同一含义字段名不同、同一人证件号写法不一。逐表梳理字段语义、建立映射字典，修正缺失异常值、消解重复，整合入 MySQL，首次让全部数据源支持联合检索。
  • ② 实体对齐与建图。以账户、自然人、企业三类实体为核心节点，依据证件号、手机号、设备信息、交易对手建关联边，把案件还原为一张可计算的关系网络。
  • ③ 关系分级加权 —— 全案关键决策，重点讲。图上低价值关联的数量远大于资金主干，等权处理会让主干被淹没。以交易金额、交易频次、关系传递层级三个维度对边施加分级权重——主干资金链自然凸显。「分析结果的可读性由这一步直接决定」——这句话要讲出来，它是全案的胜负手。
  • ④ 公开数据补全 + 路径追踪。自研爬虫采集征信平台的企业法人、股东结构、关联企业，把孤立企业节点接到真实自然人上，拓展出内部数据看不到的关联路径。然后沿加权主干逐层回溯，区分过账通道和终端归集账户，识别取现环节的卡农线索，输出按置信度排序的重点账户清单。

2收尾口述 —— 交付标准

  1. 结果「清单交给刑侦大队后逐一核实，协助勘破了该案。」
  2. 确立的交付标准「这段经历确立了我此后所有数据工作的交付标准：分析的终点是一个他人可独立核实的结论——不是一张视觉精美的关系图，也不是一组漂亮的中间指标。」
  3. 映射到现在「这个标准我后来带进了自动驾驶：每一批数据的产出都要能落到可核查的具体对象上，才具备工程价值。」

1二分查找

标准二分 变体母版 · O(log n) / O(1)

def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
  • 要点。「left + (right - left) // 2」防溢出——Python 无所谓，C++/Java 必须会。口述：有序数组、能一次排除一半的都用二分，值域单调也可以二分。

查找左边界（第一个 ≥ target）lower_bound · 变体之王

def lower_bound(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = left + (right - left) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left
  • 要点。right 取 len(nums) 开区间；相等时收缩右界不返回——left 最终停在第一个 ≥ target 处。查右边界：lower_bound(nums, target + 1) - 1。

搜索旋转排序数组 LeetCode 33 · 大厂高频 · 判断哪半有序 · O(log n)

def search_rotated(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        # 左半段有序
        if nums[left] <= nums[mid]:
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        # 右半段有序
        else:
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
    return -1
  • 要点。旋转数组一刀切成两段，必有一半是有序的——先判断哪半有序，再判断 target 在不在有序的那半里。「nums[left] <= nums[mid]」的等号在两元素时必须带上，现场最容易漏。

2排序算法

冒泡排序 最基础 · 提前终止优化 · O(n²)

def bubble_sort(nums):
    n = len(nums)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
                swapped = True
        if not swapped:
            break
    return nums
  • 要点。相邻比较、大者后移，每轮归位一个最大值。swapped 提前终止让「已有序」输入 O(n)。稳定排序。口述：教学意义大于实用，但「每轮归位一个 + 提前终止」是众多排序题的原型。

选择排序 交换次数最少 · O(n²)

def selection_sort(nums):
    n = len(nums)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if nums[j] < nums[m]:
                m = j
        if m != i:
            nums[i], nums[m] = nums[m], nums[i]
    return nums
  • 要点。每轮选剩余区间的最小值放到队首——交换次数最多 n-1 次，写内存开销敏感的场景（如闪存）反而是优点。不稳定。

插入排序 小数组/近乎有序时最快 · O(n²)

def insertion_sort(nums):
    for i in range(1, len(nums)):
        key = nums[i]
        j = i - 1
        while j >= 0 and nums[j] > key:
            nums[j + 1] = nums[j]
            j -= 1
        nums[j + 1] = key
    return nums
  • 要点。像整理扑克牌：新牌往左插到合适位置。近乎有序输入 O(n)。口述：工程上快排/归并在小区间（<16）都会切到插入排序——它在小数据上常数最小，这个细节说出来加分。

快速排序 手写概率最高 · 平均 O(n log n)，最坏 O(n²)

def quick_sort(nums, lo=0, hi=None):
    if hi is None:
        hi = len(nums) - 1
    if lo >= hi:
        return
    pivot = nums[(lo + hi) // 2]
    i, j = lo, hi
    while i <= j:
        while nums[i] < pivot:
            i += 1
        while nums[j] > pivot:
            j -= 1
        if i <= j:
            nums[i], nums[j] = nums[j], nums[i]
            i += 1
            j -= 1
    quick_sort(nums, lo, j)
    quick_sort(nums, i, hi)
  • 要点。双指针分区，原地、不稳定；取中间元素做 pivot 避开已排序数组的最坏情况。口述：最坏是分区极度不平衡退化为 O(n²)，工程上随机取 pivot 兜底。

归并排序 稳定 · O(n log n) 有保证 · 外部排序的基础

def merge_sort(nums):
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])
    return merge(left, right)

def merge(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    result.extend(a[i:])
    result.extend(b[j:])
    return result
  • 要点。「<=」取等号保稳定性，空间 O(n)。口述：大数据排序用归并——分块落盘、多路归并，正是数仓外部排序的原理。

堆 · Top-K 海量数据第 K 大 · O(n log k)

import heapq

def top_k_largest(nums, k):
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return sorted(heap, reverse=True)
  • 要点。求最大 K 个用小顶堆（堆顶是第 K 大的守门员）。口述：海量数据 Top-K = 分治 + 堆——每台机器本地取 Top-K，汇总再取一次，MapReduce 同思路。

3哈希类

两数之和 O(n²) → O(n) · 空间换时间

def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
  • 要点。先查后存——同一元素不会用两次。「存在性问题先想哈希」的起点题。

字母异位词分组 设计哈希键是核心

from collections import defaultdict

def group_anagrams(strs):
    groups = defaultdict(list)
    for s in strs:
        key = ''.join(sorted(s))
        groups[key].append(s)
    return list(groups.values())
  • 要点。排序后的串做键 O(k log k)；进阶用 26 位计数元组做键 O(k)。口述：这类题的本质是「怎么把等价类映射到同一个键」。

第一个只出现一次的字符 剑指 Offer 50 · 两遍扫哈希计数

from collections import Counter

def first_uniq_char(s):
    count = Counter(s)
    for i, ch in enumerate(s):
        if count[ch] == 1:
            return i
    return -1
  • 要点。第一遍计数、第二遍按原顺序找计数为 1 的——顺序信息只有原串有，哈希表只存频次。数据侧映射：按批次统计标签出现次数后找「只出现一次的异常标注」。

4双指针

原地删除有序数组重复项 快慢指针模板

def remove_duplicates(nums):
    if not nums:
        return 0
    slow = 0
    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow]:
            slow += 1
            nums[slow] = nums[fast]
    return slow + 1
  • 要点。slow 指向已处理区末尾，fast 探路。快慢指针适用于「保留符合条件的、原地压缩」一切场景——迁移到工作就是按批次去重。

三数之和 排序 + 固定一个 + 双指针 · 去重是考点

def three_sum(nums):
    nums.sort()
    result = []
    n = len(nums)
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        if nums[i] > 0:
            break
        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
    return result
  • 要点。两层去重：i 层跳过重复的固定值，命中后 left/right 也要跳重复。O(n²)。面试官看的就是去重细节——漏一处就有重复三元组。

盛最多水的容器 对撞指针 · 每次移动短板

def max_area(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        area = (right - left) * min(height[left], height[right])
        best = max(best, area)
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1
    return best
  • 要点。移动短板才可能变大（移动长板：宽度减一、高度仍被短板限制，必不优）。O(n)。对撞指针的正确性证明要会说。

接雨水 LeetCode 42 · 困难高频 · 对撞双指针 O(n)/O(1)

def trap(height):
    left, right = 0, len(height) - 1
    left_max = right_max = 0
    water = 0
    while left < right:
        if height[left] < height[right]:
            left_max = max(left_max, height[left])
            water += left_max - height[left]
            left += 1
        else:
            right_max = max(right_max, height[right])
            water += right_max - height[right]
            right -= 1
    return water
  • 要点。每格水量 = min(左边最高, 右边最高) - 自身高度。对撞版妙处：矮的那侧更新后，left_max ≤ right_max 必然成立，直接结算不必等两边扫完。先讲清「按列求」的模型，再给这版实现。

5滑动窗口

无重复字符的最长子串 窗口模板入门 · O(n)

def length_of_longest_substring(s):
    last = {}
    best = 0
    left = 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best
  • 要点。「last[ch] >= left」防止窗口左移回退。口述：滑动窗口 = 右指针扩张、左指针按条件收缩，每个字符最多进出一次，所以 O(n)。

最小覆盖子串 窗口模板进阶 · 收缩时机是难点

from collections import Counter

def min_window(s, t):
    need = Counter(t)
    missing = len(t)
    left = 0
    best = (0, 0)
    for right, ch in enumerate(s):
        if need[ch] > 0:
            missing -= 1
        need[ch] -= 1
        if missing == 0:
            while need[s[left]] < 0:
                need[s[left]] += 1
                left += 1
            if best == (0, 0) or right - left < best[1] - best[0]:
                best = (left, right + 1)
            need[s[left]] += 1
            missing += 1
            left += 1
    return s[best[0]:best[1]]
  • 要点。missing 计数器代替每次比较 need 与 window；窗口刚好满足时收缩到极限、记录、再放掉左端继续。Counter 缺键返回 0 不报错，是这版简洁的关键。

和为 K 的子数组 LeetCode 560 · 前缀和 + 哈希 · 负数存在时滑动窗口失效

from collections import defaultdict

def subarray_sum(nums, k):
    count = defaultdict(int)
    count[0] = 1          # 空前缀，从头开始的子数组能被计数
    prefix = 0
    result = 0
    for x in nums:
        prefix += x
        result += count[prefix - k]   # 之前有多少个前缀和 = prefix - k
        count[prefix] += 1
    return result
  • 要点。「子数组和 → 前缀和之差」：sum(i..j) = prefix[j] - prefix[i-1]，目标变成查「之前出现过多少个 prefix - k」。count[0] = 1 是最容易漏的初始化。数组含负数时窗口不单调，只能用这招——主动说出这个判断是加分点。

6链表

反转链表 迭代三指针 · 必须盲写

def reverse_list(head):
    prev = None
    curr = head
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt
    return prev
  • 要点。先存 next 再断链。口述：四个赋值一循环，画图讲最清楚。返回 prev——它是新头。

环形链表检测 + 入口 快慢指针 · Floyd 判圈

def detect_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            entry = head
            while entry is not slow:
                entry = entry.next
                slow = slow.next
            return entry
    return None
  • 要点。相遇后一个指针回头，同速再走，再相遇即入口——数学结论（a = c 等距关系）要能口述。应用映射：数据链路里检测循环依赖。

合并两个有序链表 哨兵节点省判空

def merge_two_lists(l1, l2):
    dummy = ListNode(0)
    tail = dummy
    while l1 and l2:
        if l1.val <= l2.val:
            tail.next = l1
            l1 = l1.next
        else:
            tail.next = l2
            l2 = l2.next
        tail = tail.next
    tail.next = l1 if l1 else l2
    return dummy.next
  • 要点。dummy 哨兵消掉「头节点谁当」的特判；尾插完剩余段直接接上。归并排序链表版的核心子过程。

两个链表的第一个交点 双指针走对方的路

def get_intersection(a, b):
    p, q = a, b
    while p is not q:
        p = p.next if p else b
        q = q.next if q else a
    return p
  • 要点。两指针走的总长都是 a + b，无交点时同一时刻到达 None。O(n+m) / O(1)。不看长度、不拼接——面试官喜欢这版。

链表的中间节点 LeetCode 876 · 快慢指针一次遍历

def middle_node(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow
  • 要点。fast 走两步、slow 走一步，fast 到尾时 slow 恰在中点（偶数长度停在右中点）。它是「归并排序找中点」「回文链表找中点再反转后半段」的子过程——快慢指针三件套之一。

7栈与队列

有效括号 栈的经典应用 · O(n)

def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()
        else:
            stack.append(ch)
    return not stack
  • 要点。右括号查栈顶是否对应左括号；最后栈必须为空（漏判「((」）。映射工作：表达式解析、配置文件结构校验。

用两个栈实现队列 考察数据结构转换 · 均摊 O(1)

class MyQueue:
    def __init__(self):
        self.in_stack = []
        self.out_stack = []

    def push(self, x):
        self.in_stack.append(x)

    def _shift(self):
        if not self.out_stack:
            while self.in_stack:
                self.out_stack.append(self.in_stack.pop())

    def pop(self):
        self._shift()
        return self.out_stack.pop()

    def peek(self):
        self._shift()
        return self.out_stack[-1]

    def empty(self):
        return not self.in_stack and not self.out_stack
  • 要点。in 转 out 才能倒序；只在 out 空时倾倒——均摊 O(1)。口述：队头永远在 out 栈顶，转移时机是关键。

每日温度 LeetCode 739 · 单调栈模板 · 下一个更大元素

def daily_temperatures(temperatures):
    result = [0] * len(temperatures)
    stack = []                      # 存下标，栈内温度单调递减
    for i, t in enumerate(temperatures):
        while stack and temperatures[stack[-1]] < t:
            j = stack.pop()
            result[j] = i - j       # 栈顶等到了更暖的一天
        stack.append(i)
    return result
  • 要点。「下一个更大」类问题标准解法：栈里存还没等到答案的下标，新元素来了把所有比它小的都结算掉。「求下一个/上一个更大更小」共四种变体，全是这一模板改比较方向。

8动态规划

爬楼梯 DP 入门 = 斐波那契

def climb_stairs(n):
    if n <= 2:
        return n
    prev, curr = 1, 2
    for _ in range(3, n + 1):
        prev, curr = curr, prev + curr
    return curr
  • 要点。dp[i] = dp[i-1] + dp[i-2]，滚动变量压到 O(1)。被追问就讲状态定义：到第 i 阶的走法数。

打家劫舍 选或不选 · 相邻不能连选

def rob(nums):
    prev, curr = 0, 0
    for x in nums:
        prev, curr = curr, max(curr, prev + x)
    return curr
  • 要点。curr = 不抢当前（沿用 curr）或抢（prev + x）的最大值。一行状态转移，「偷不偷当前」决策类模板。

最大子数组和 Kadane · O(n) 一遍扫

def max_sub_array(nums):
    best = curr = nums[0]
    for x in nums[1:]:
        curr = max(x, curr + x)
        best = max(best, curr)
    return best
  • 要点。curr = 前缀贡献为正则延续、为负则从当前重新开始。口述：负收益的历史直接丢弃——数据侧对应「连续区间指标分析」。

零钱兑换 LeetCode 322 · 完全背包 · 大厂高频

def coin_change(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1
  • 要点。dp[a] = 凑出金额 a 的最少硬币数；「凑不出」用 inf 哨兵而不是 -1，转移才不会被污染。口述模板：问最少/最多方案数就是完全背包，外层金额、内层硬币，顺序无所谓；若问「组合数」内外层必须交换（先硬币后金额）——能否说出这个区别是区分度所在。

最长公共子序列 LeetCode 1143 · 二维 DP 代表作 · diff 工具的原理

def longest_common_subseq(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]
  • 要点。二维表格：字符相等从左上角 +1，不相等取上/左最大。第 0 行第 0 列天然为 0 不用初始化。映射工程：git diff、标注文件版本对比，底层都是 LCS。

from collections import deque

def level_order(root):
    if not root:
        return []
    result = []
    queue = deque([root])
    while queue:
        layer = []
        for _ in range(len(queue)):
            node = queue.popleft()
            layer.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(layer)
    return result
  • 要点。「for _ in range(len(queue))」是分层关键——先记当前层节点数再消费。标签树的层级遍历同构，可主动映射。

最近公共祖先 递归定义清晰即答对

def lowest_common_ancestor(root, p, q):
    if root is None or root is p or root is q:
        return root
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    if left and right:
        return root
    return left if left else right
  • 要点。p、q 分居两侧时当前节点即答案；都在一侧则答案在那侧。映射标签树：两个标签的最近公共父标签。

def is_valid_bst(root):
    def check(node, lo, hi):
        if node is None:
            return True
        if not (lo < node.val < hi):
            return False
        return check(node.left, lo, node.val) and \
               check(node.right, node.val, hi)
    return check(root, float('-inf'), float('inf'))

岛屿数量 LeetCode 200 · 网格 DFS 母题 · 字节/阿里高频

def num_islands(grid):
    if not grid:
        return 0
    rows, cols = len(grid), len(grid[0])
    count = 0

    def dfs(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return
        if grid[r][c] != '1':
            return
        grid[r][c] = '0'          # 沉岛：访问过直接改标记
        dfs(r + 1, c); dfs(r - 1, c)
        dfs(r, c + 1); dfs(r, c - 1)

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                count += 1
                dfs(r, c)
    return count
  • 要点。遍历到陆地就计数 +1，然后 DFS 把整块连通的陆地全部「沉掉」——每个岛屿只被计一次。网格四方向递归 + 越界/访问判断，是所有网格搜索题的骨架。追问会变体：最大岛屿面积（返回 dfs 计数）、岛屿周长。

腐烂的橘子 LeetCode 994 · 多源 BFS · 按层扩散求最短时间

from collections import deque

def oranges_rotting(grid):
    rows, cols = len(grid), len(grid[0])
    queue = deque()
    fresh = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == 2:
                queue.append((r, c))
            elif grid[r][c] == 1:
                fresh += 1

    minutes = 0
    while queue and fresh:
        minutes += 1
        for _ in range(len(queue)):       # 一轮 = 一分钟
            r, c = queue.popleft()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1:
                    grid[nr][nc] = 2
                    fresh -= 1
                    queue.append((nr, nc))
    return minutes if fresh == 0 else -1
  • 要点。多源 BFS：所有腐烂橘子同时入队当第 0 层，「按层消费」让每层 = 一分钟。「求最少步数/最短时间用 BFS 不用 DFS」——无权图上 BFS 第一次到达即最短。fresh == 0 的收尾判断别漏。

11字符串

验证回文串 过滤 + 对撞双指针

def is_palindrome(s):
    chars = [c.lower() for c in s if c.isalnum()]
    left, right = 0, len(chars) - 1
    while left < right:
        if chars[left] != chars[right]:
            return False
        left += 1
        right -= 1
    return True
  • 要点。isalnum 过滤标点空格再对撞比较。先过滤后比较，不要在原串上跳指针（易越界）。

最长回文子串 中心扩展 · O(n²) 但常数小、现场不易写错

def longest_palindrome(s):
    def expand(left, right):
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        return s[left + 1:right]

    if not s:
        return ''
    best = s[0]
    for i in range(len(s)):
        cand = max(expand(i, i), expand(i, i + 1), key=len)
        if len(cand) > len(best):
            best = cand
    return best
  • 要点。奇偶两种中心（i 单字符、i 与 i+1 双字符）。会 DP 也可讲 O(n²) 表格法，但中心扩展现场更稳。

12设计题

LRU 缓存 LeetCode 146 · 大厂必考 · 哈希 + 双向链表 · O(1)

class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.map = {}                       # key -> 节点
        self.head, self.tail = Node(), Node()  # 哨兵：head 新、tail 旧
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_front(self, node):
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)                  # 访问即最新：摘下插到队头
        self._add_front(node)
        return node.val

    def put(self, key, value):
        if key in self.map:
            self._remove(self.map[key])
        node = Node(key, value)
        self.map[key] = node
        self._add_front(node)
        if len(self.map) > self.cap:        # 淘汰队尾（最久未用）
            lru = self.tail.prev
            self._remove(lru)
            del self.map[lru.key]           # 节点里存 key 才能反向删 map
  • 要点。两个哨兵节点消掉所有判空——头尾永远存在，指针操作只有四行。get/put 都是「摘下插队头」；超容量删 tail.prev。节点里必须存 key：淘汰链表节点时要反删哈希表。口述：Python 面试可直接说 OrderedDict / functools.lru_cache 十行实现，但手写版才是考点。

旋转数组（三段反转）O(n) 时间 O(1) 空间

def rotate(nums, k):
    n = len(nums)
    if n == 0:
        return
    k %= n
    nums.reverse()
    nums[:k] = reversed(nums[:k])
    nums[k:] = reversed(nums[k:])
  • 要点。整体反转 → 前 k 反转 → 余下反转，画一次图就永远记得。注意 k %= n 防 k 大于长度。

【什么是 LMDB】
═══════════════════════════════════════════════════════════════════════════
LMDB (Lightning Memory-Mapped Database) 是一个基于 B+ 树、基于内存映射
(mmap) 的嵌入式键值数据库（不需要独立的数据库服务进程）。特点：
  - 读性能极高（数据直接 mmap 到进程地址空间，读取零拷贝）；
  - 支持多进程并发只读（配合 readonly + lock=False）；
  - 写入基于事务（ACID），数据按 key 有序存储；
  - 单文件（实际上是 data.mdb + lock.mdb 两个文件）便于打包和分发。
因此深度学习领域常用它存储训练数据：每条样本（序列化后的图片+标注 bytes）
是一个 value，样本序号（字符串化的整数）是 key。
Caffe 生态最早大规模使用，后来 Horizon/地平线的训练框架也普遍采用。

═══════════════════════════════════════════════════════════════════════════
【典型使用方式】
═══════════════════════════════════════════════════════════════════════════
写入侧（数据打包脚本）：
    db = Lmdb("/path/to/data.lmdb", writable=True)   # 写模式打开
    for i, record in enumerate(records):             # record: bytes
        db.write(i, record)                          # key=b'0', b'1', ...
    db.write("__len__", str(len(records)).encode())  # 可选：记录总条数
    db.close()                                       # 尾部commit + sync落盘

读取侧（训练 dataloader）：
    db = Lmdb("/path/to/data.lmdb", writable=False)  # 只读模式，多进程可并发
    keys = db.get_keys()                             # 所有可用 key
    data = db.read(0)                                # 读第 0 条样本 -> bytes

"""

class PackType(ABC):
    """Data type interface class.

    ────────────────────────────────────────────────────────────────────
    【角色】数据打包类型的抽象基类 = "数据文件应该长什么样"的接口契约。
    ────────────────────────────────────────────────────────────────────

    设计动机（为什么需要这个类）：
      打包训练数据可能选用不同的底层格式（LMDB / MXNet REC / 纯文件夹...）。
      如果上层代码直接写 `import lmdb; lmdb.open(...)`，格式就被焊死了。
      引入 PackType 后，上层只调用统一接口：
          packer: PackType = Lmdb(...)      # 或未来换成 Rec(...)
          packer.write(i, record)
      底层格式切换时上层代码不需要任何修改——这就是"依赖抽象而非实现"
      （依赖倒置原则）的具体落地。

    抽象方法说明（子类必须提供的完整生命周期）：
        open()      打开文件，建立连接       ← 生命周期的开始
        write()     写入一条记录            ← 打包阶段
        read()      读取一条记录            ← 训练读取阶段
        get_keys()  获取全部可读 key        ← 读取侧遍历索引
        __len__()   获取记录总数            ← 读取侧知道数据集大小
        reset()     重置句柄                ← 异常恢复（句柄失效时重开）
        close()     关闭并落盘              ← 生命周期的结束
        __del__()   析构兜底                ← 防止用户忘记 close 造成泄漏

    接口约定（隐含的契约，子类实现时必须遵守）：
      1. write(idx, record)：key 由整数 idx 转化而来，record 是 bytes；
      2. read(idx)：写入时的 idx 就是读取时的 idx，即 write/read 用同一套 key；
      3. 所有方法应当可重复安全调用（幂等），尤其是 open/close；
      4. close 之后再次 read/write 应能自动重新打开（懒加载恢复），
         本文件的 Lmdb 实现即按此约定做了懒加载处理。
    """

    def open(self):
        """Open the data file.
        打开数据文件并建立可用的读写连接（句柄）。
        约定：若文件已打开则不重复打开（幂等）。"""

    def close(self):
        """Close the data file.
        关闭数据文件：写模式下需保证未提交的数据完整落盘，
        然后释放文件句柄等系统资源。
        约定：若文件未打开则不做任何事（幂等）。"""

    def write(self, idx: int, record: bytes):
        """Write record into data file by idx.
        以 idx 为 key、record 为 value 写入一条记录。
        参数:
            idx: 样本序号（整数），子类负责把它转成底层格式需要的 key
                 （LMDB 中通常转为 ascii bytes，如 123 -> b'123'）；
            record: 一条完整的序列化样本数据（bytes），通常是
                    "图片二进制 + 标注信息" 打包后的结果。"""

    def read(self, idx):
        """Read the idx-th data.
        按 idx 读取一条记录，返回 bytes。
        idx 与 write 时的 idx 一一对应。"""

    def reset(self):
        """Reset the data file operator.
        重置文件操作句柄：先关闭再重新打开。
        使用场景：长时间运行的进程中，文件句柄可能因网络文件系统
        断连、超时等原因失效，调用 reset 可以拿到全新的句柄恢复工作。"""

    def get_keys(self):
        """Get keys for read.
        返回文件中所有可读取的 key（可迭代对象）。
        读取侧用它在不知道样本分布的情况下遍历整个数据集，
        通常配合 read(key) 逐条取样本。"""

    def __del__(self):
        """Recycle resources.
        析构方法：对象被 Python 垃圾回收（引用计数归零 / 解释器退出）时
        自动调用，这里调用 self.close() 兜底释放资源。
        目的：即使用户代码忘记显式 close()，也能在对象销毁时尽量完成
        提交与关闭，防止数据丢失和句柄泄漏。
        注意：__del__ 的调用时机不可靠（循环引用、解释器退出时可能不执行），
        所以这只是"兜底保险"，正常流程仍应显式调用 close()。"""
        self.close()

    def __len__(self):
        """Get the length.
        返回文件中记录的总条数。
        实现了 __len__ 后即可使用内置 len(obj) 语法，
        也使对象能被 bool() 判断（非空即 True）并参与一些期望 Sized
        协议的框架代码。"""


class Lmdb(PackType):
    """Class of LMDB, which include all operators.

    ────────────────────────────────────────────────────────────────────
    【角色】PackType 的 LMDB 具体实现，包含 LMDB 文件的全部读写操作。
    ────────────────────────────────────────────────────────────────────

    Args:
        uri: Path to lmdb file.
            LMDB 路径。注意 lmdb.open 接收的是"目录"路径：
            打开/创建后该目录下会出现 data.mdb（数据文件）和
            lock.mdb（写锁文件）两个文件。
        writable: Writable flag for opening LMDB.
            - True（默认）：写模式，用于打包数据集；
            - False：只读模式，用于训练时读取。内部会自动追加
              readonly=True / lock=False 两个 lmdb 参数（见 __init__），
              不加文件锁，从而允许 DataLoader 多个 worker 进程并发读。
        flush_before_write: Whether to reopen file while writing.
            写之前是否需要重新打开文件的标志位。（本实现中仅保存该
            标志，未在写路径上强制执行，属于预留参数。）
        commit_step: The step for commit.
            每写入多少条记录执行一次事务提交，默认 5000。
            为什么需要分批提交：
              LMDB 中一次事务的所有修改先落在空闲页，commit 时才真正
              生效；单个事务过大 → 占用的磁盘空间和内存都会膨胀，
              提交本身也变慢。分批提交把事务尺寸控制在常数级别；
              同时已提交的数据即时持久化，异常中断时最多丢失最近
              不足 commit_step 条的数据。
        kwargs: Kwargs for open lmdb file.
            其他透传给 lmdb.open() 的关键字参数，可覆盖下方
            "default lmdb settings" 中的任何默认值。
    """

    def __init__(
        self,
        uri: str,
        writable: bool = True,
        flush_before_write: bool = False,
        commit_step: int = 5000,
        **kwargs,
    ):
        # ---- 1. 保存基础配置 ----
        self.uri = uri                      # LMDB 目录路径，open/close/reset 时使用
        self.writable = writable            # 读写模式标志，决定事务以 write=True/False 开启
        self.flush_before_write = flush_before_write  # 预留标志位（见类 docstring）
        self.kwargs = kwargs                # lmdb.open 的原始参数字典（含用户自定义）

        # ---- 2. 填充 LMDB 默认参数（用户已显式传入的优先，不覆盖）----
        # dict.get(key, default): key 存在则返回已有值，否则返回 default。
        # 由此实现"默认值 + 可被 kwargs 覆盖"的参数机制。

        # map_size: 数据库文件映射空间上限（字节）。
        # LMDB 必须预先声明最大容量（mmap 区域大小），写入总量不能超过它。
        # 默认 1024**4 = 1TB，给到足够大，免去用户估算数据集大小的负担。
        self.kwargs["map_size"] = self.kwargs.get("map_size", 1024**4)
        # meminit: 为 False 表示 mmap 时不用 0 预填充新写入的内存页，
        # 可以显著加快首次写入大 map_size 时的初始化速度。
        self.kwargs["meminit"] = self.kwargs.get("meminit", False)
        # map_async: 为 True 时使用 MDB_MAPASYNC，flush 操作交给后台异步执行，
        # 配合下面的 sync=False 组成高性能写入配置。
        self.kwargs["map_async"] = self.kwargs.get("map_async", True)
        # sync: 为 False 表示 commit 后不立刻 fsync 强制刷盘，
        # 数据先缓存在操作系统页缓存中，写入吞吐更高；
        # 代价：断电等极端情况下可能丢失最后一批数据（打包场景可接受，
        # close() 中会显式调用 env.sync() 做最终落盘）。
        self.kwargs["sync"] = self.kwargs.get("sync", False)
        if not writable:
            # 只读模式的两个关键参数：
            # readonly=True: 以只读方式打开，若文件不存在会直接报错
            #               （避免误创建空库导致读到空数据）；
            # lock=False:   不获取文件锁。这是多进程并发读的必要条件——
            #               若加锁，DataLoader 的多个 worker 会互相阻塞。
            self.kwargs["readonly"] = True
            self.kwargs["lock"] = False

        # ---- 3. 初始化句柄并打开文件 ----
        # LMDB 两级核心句柄：
        #   env: Environment 环境句柄 —— 对应整个 LMDB 文件（mmap 映射），
        #        一个 env 下可开多个事务；
        #   txn: Transaction 事务句柄 —— LMDB 的所有读写都必须在事务中进行，
        #        写事务需要显式 commit 才生效，读事务随用随开。
        # 先置 None，open() 内部判断 env is None 才真正执行打开（幂等）。
        self.env = None
        self.txn = None
        self.open()                  # 打开 env（写模式此时不开事务，写入时懒加载）
        if not self.writable:
            # 只读模式构造时立即建立读事务，后续 get/read 直接可用；
            # 写模式不提前开事务，等第一次 write 时再建（懒加载，
            # 也避免空库时白开一个写事务占用资源）。
            self._create_txn()
        # ---- 4. 写入侧的批次控制状态 ----
        self.commit_step = commit_step  # 每多少条 commit 一次
        self.put_idx = 0                # 自构造以来累计写入的条数，
                                        # 用于 write() 中判断是否到达提交点

    def read(self, idx: Union[int, str]) -> bytes:
        """Read data by idx.
        按索引读取一条记录（对外接口，带异常日志）。

        参数 idx 允许两种类型（Union[int, str]）：
            int  —— 常规样本序号，如 read(0)、read(123)；
            str  —— 字符串 key，如 read("__len__") 读打包时写入的总数。

        key 的编码约定："{}".format(idx).encode("ascii")
            先把 idx 格式化为字符串（123 -> "123"），
            再编码成 ascii bytes（"123" -> b"123"）。
            LMDB 的 key 必须是 bytes；写入(write)和读取(read/get)使用
            完全相同的编码，保证两侧 key 一致才能命中。
        """
        idx = "{}".format(idx).encode("ascii")
        try:
            return self.get(idx)     # 委托给带超时的底层 get 方法
        except TimeoutError as exception:
            # 捕获的是 timeout_decorator 抛出的超时异常（非内置 TimeoutError）。
            # 先用 logger.error 记录上下文（哪个 key、哪个文件），
            # 再原样 raise 让上层感知并决定重试或终止。
            logger.error(
                f"Time out when reading data with index of "
                f"{idx} from {self.uri}"
            )
            raise exception

    @timeout(seconds=600)  # 读操作 600 秒（10 分钟）硬超时，防 NFS 挂死
    def get(self, idx: Union[int, str]) -> bytes:
        """底层读取方法（类内部使用，带超时装饰器）。
        idx 此时已是编码好的 bytes key。
        若事务句柄不存在（从未创建 / close 后被清空），先懒加载重建，
        再执行 txn.get(key) 返回对应 value（bytes）；key 不存在时返回 None。"""
        if self.txn is None:
            self._create_txn()
        return self.txn.get(idx)

    def write(self, idx: Union[int, str], record: bytes):
        """Write data into lmdb file.
        写入一条记录（打包数据集的核心方法）。

        执行流程（逐步）：
          ① 懒加载恢复：若 env 为 None（曾被 close），重新打开文件；
          ② 懒加载事务：若 txn 为 None，创建新事务；
          ③ 编码写入：idx 统一转 ascii bytes 作 key，txn.put 写入当前事务；
          ④ 计数：put_idx 累加，记录本事务周期内已写条数；
          ⑤ 分批提交：每写满 commit_step 条（put_idx 能被整除）执行
             txn.commit() 使数据真正生效，随后 env.begin() 开启新事务
             继续接收后续写入（旧事务 commit 后不可再使用）。
        """
        if self.env is None:
            self.open()              # ① close 之后再次 write，自动重开
        if self.txn is None:
            self._create_txn()       # ② 无事务则建事务
        # ③ key 编码与 read 完全一致；record 是完整的样本 bytes
        self.txn.put("{}".format(idx).encode("ascii"), record)
        self.put_idx += 1            # ④ 累计写入计数
        if self.put_idx % self.commit_step == 0:
            # ⑤ 到达提交点：% 取模为 0 说明刚写满一批（5000 条），
            #    commit 后旧事务生命周期结束，必须重新 begin 一个新事务。
            self.txn.commit()
            self.txn = self.env.begin(write=self.writable)

    @timeout(seconds=600)  # 打开操作 600 秒硬超时：网络存储挂载故障时不至于无限等待
    def open_lmdb(self):
        """真正调用 lmdb.open 的地方（被 @timeout 包装）。
        把 lmdb.open 单独抽成一个方法，是为了让超时装饰器只作用于
        这一个系统调用——装饰 open() 整个方法会连带把内部逻辑一起计时，
        粒度不够精确。"""
        return lmdb.open(self.uri, **self.kwargs)

    def open(self):
        """Open lmdb file.
        打开 LMDB 环境（对外接口，幂等）。
        仅当 env 为 None（尚未打开 / 已被 close）时才真正执行 open，
        重复调用不会重复打开，也不会产生句柄泄漏。"""
        if self.env is None:
            try:
                self.env = self.open_lmdb()   # 拿到 Environment 句柄
            except TimeoutError as exception:
                # 打开超时（典型于 NFS 故障/文件被异常挂起）：记录日志后上抛
                logger.error(f"Time out when opening {self.uri}")
                raise exception

    def _create_txn(self):
        """Create lmdb transaction.（内部方法，下划线开头表示类内部使用）
        创建事务句柄，两级保证：
          ① env 未打开则先打开（事务必须依附于环境）；
          ② txn 为 None 时才创建，按 self.writable 决定事务类型：
             写模式  -> env.begin(write=True)  写事务，需 commit 生效；
             只读模式-> env.begin(write=False) 读事务，用完即弃。"""
        if self.env is None:
            self.open()
        if self.txn is None:
            self.txn = self.env.begin(write=self.writable)

    def close(self):
        """Close lmdb file.
        关闭 LMDB 文件（对外接口，幂等）。

        写模式下的完整收尾流程（保证数据不丢）：
          ① 判断 env 存在才有得关（幂等：未打开直接跳过）；
          ② 写模式下若事务存在：
             - put_idx % commit_step != 0 说明最后一批不满 5000 条、
               尚未 commit，这里补一次 commit 把尾部数据落库；
             - put_idx 清零，支持 close 后重新打开继续写的场景；
             - env.sync() 强制 fsync 刷盘 —— 弥补构造时 sync=False 的
               异步配置，确保进程退出前数据真正写入磁盘。
          ③ env.close() 关闭映射并释放资源，句柄全部置 None，
             触发后续 read/write 的懒加载重开逻辑。"""
        if self.env is not None:                         # ① 幂等保护
            if self.writable and self.txn is not None:   # ② 仅写模式需要收尾
                if self.put_idx % self.commit_step != 0:
                    self.txn.commit()                    # ② 补交尾部数据
                self.put_idx = 0                         # ② 计数复位
                self.env.sync()                          # ② 强制刷盘
            self.env.close()                             # ③ 关闭环境
            self.env = None
            self.txn = None

    def reset(self):
        """Reset open file.
        重置文件句柄（异常恢复手段）。

        分支逻辑：
          - env 和 txn 都为 None：说明文件根本没打开，直接 open 打开即可；
          - 否则（任一不为 None）：先 close（写模式会先 commit+sync，
            保证已有数据安全）再 open，最终得到一个全新的、干净的句柄。
        使用场景：长时间运行中句柄失效（NFS 断连、超时后状态可疑），
        或者想要"清空缓冲、从头开始"的状态。"""
        if self.env is None and self.txn is None:
            self.open()
        else:
            self.close()
            self.open()

    def get_keys(self):
        """Get all keys.
        获取全部可读 key（读取侧建立索引用）。

        两级策略（fast path / slow path）：
          快路径 —— 读取特殊 key "__len__"（编码为 b'__len__'）。
              部分打包工具会在收尾时写入总条数（如 write("__len__", b"10000")）。
              若该 key 存在，直接返回 range(N) —— 即 [0, 1, ..., N-1]，
              因为打包时 key 就是连续整数，无需真正遍历数据库，开销 O(1)。
          慢路径 —— 若快路径抛任何异常（key 不存在返回 None，
              int(None) 会抛 TypeError），则用 cursor 游标逐条迭代
              整个数据库收集真实 key 列表。注释也点明了：
              key 数量很大时全量遍历可能很慢，所以才优先走快路径。
        """
        if self.txn is None:
            self._create_txn()          # 保证有可用事务
        try:
            idx = "{}".format("__len__").encode("ascii")  # -> b'__len__'
            # txn.get 返回 bytes（如 b'10000'），int() 还原为整数 N，
            # range(N) 是惰性序列，不占内存。
            return range(int(self.txn.get(idx)))
        except Exception:
            # traversal may be slow while too much keys
            # 游标迭代：yield (key, value) 对，这里只要 key 不要 value。
            # 返回的 key 是原始 bytes（如 b'0', b'1' ...），
            # 调用方需自行处理类型（read() 对 str/bytes 的 format 结果一致，
            # 所以 bytes key 也能直接传给 read）。
            keys = []
            for key, _value in self.txn.cursor():
                keys.append(key)
            return keys

    def __len__(self):
        """Get the length.
        返回数据集总条数（实现了它就可以直接 len(db)）。

        两级策略与 get_keys 一致：
          快路径 —— 读特殊 key "__len__" 里存的条数；
          慢路径 —— 快路径失败时改用 LMDB 内置统计：
                    txn.stat()["entries"] 返回数据库中的 key 总数。
                    注意：entries 统计所有 key，若打包时额外写入过
                    "__len__" 这类元数据 key，结果会比真实样本数多 1，
                    属于已知的小误差。"""
        if self.txn is None:
            self._create_txn()
        try:
            idx = "{}".format("__len__").encode("ascii")
            return int(self.txn.get(idx))
        except Exception:
            # stat() 返回字典：{"entries": 条数, "psize": 页大小, ...}
            return self.txn.stat()["entries"]

    def __getstate__(self):
        """pickle 序列化钩子（配合 multiprocessing / DataLoader 使用）。

        触发时机：对象被 pickle.dumps 或跨进程传递（如作为 DataLoader
        dataset 被发到 worker 进程）时自动调用。

        为什么必须实现：
          lmdb 的 env/txn 底层是 C 指针和 mmap 映射，属于进程私有资源，
          无法被序列化——直接 pickle 会失败或产生悬空指针。

        做法：返回 self.__dict__（包含 uri/writable/kwargs 等纯配置，
        以及此时仍非 None 的 env/txn 引用），但返回前先调用 self.close()。
        注意 close() 会把 self.__dict__ 里的 env/txn 置为 None，因此
        实际被序列化的状态中句柄已是 None，子进程收到后不会拿到
        任何失效的 C 指针。"""
        state = self.__dict__
        self.close()      # 关闭本进程的句柄（数据已 commit+sync，安全）
        return state      # state["env"]/state["txn"] 此时均为 None

    def __setstate__(self, state):
        """pickle 反序列化钩子（__getstate__ 的逆操作）。

        触发时机：子进程 unpickle 还原本对象时自动调用。
        做法：先恢复全部属性字典，再调用 self.open() 在【当前进程】
        重新打开 LMDB 文件、重建自己的 env 句柄（只读模式下 open 后
        需要的读事务会在首次 get 时通过 _create_txn 懒加载建立）。
        由此保证每个进程持有独立的、指向同一文件的合法句柄，
        配合 readonly+lock=False 实现多进程安全并发读。"""
        self.__dict__ = state
        self.open()

def mock_pack(lmdb_dir: str, num_samples: int = 23, commit_step: int = 5):
    """模拟真实打包脚本的行为：
    - 写模式打开（writable=True）
    - 以连续整数 idx 为 key 逐条写入样本 bytes
    - 收尾写入 "__len__" 记录总条数
    - close() 触发尾部 commit + sync 落盘

    commit_step 故意设小（5），验证 write() 的分批提交逻辑：
    23 条数据会触发 4 次 commit（5/10/15/20），最后 3 条由 close 补交。
    """
    if os.path.exists(lmdb_dir):
        shutil.rmtree(lmdb_dir)  # lmdb.open 要求目录不存在或为空

    db = Lmdb(lmdb_dir, writable=True, commit_step=commit_step)
    for i in range(num_samples):
        # 真实场景这里是 "图片二进制 + 标注序列化" 后的 bytes，
        # debug 用带 magic header 的假数据即可
        record = b"FAKE_JPEG_MAGIC" + b"sample-%04d" % i
        db.write(i, record)
    db.write("__len__", str(num_samples).encode("ascii"))
    db.close()
    logger.info(f"[pack] 写入完成: {num_samples} 条 + __len__, 目录: {lmdb_dir}")
    logger.info(
        f"[pack] 目录内容: {sorted(os.listdir(lmdb_dir))}"
        f"  (应为 data.mdb + lock.mdb)"
    )


def verify(lmdb_dir: str, num_samples: int = 23):
    """读取校验（读侧，模拟训练 dataloader 视角）。"""
    db = Lmdb(lmdb_dir, writable=False)  # readonly + lock=False

    # ---- 1. len()：走 __len__ 快路径 ----
    total = len(db)
    assert total == num_samples, f"len 失败: {total} != {num_samples}"
    logger.info(f"[read] len(db) = {total}  ✓ 走 __len__ 快路径")

    # ---- 2. get_keys()：走 __len__ 快路径，返回 range(N) ----
    keys = list(db.get_keys())
    assert keys == list(range(num_samples)), f"keys 异常: {keys[:5]}..."
    logger.info(f"[read] get_keys() = range({num_samples})  ✓")

    # ---- 3. 逐条读取并校验内容 ----
    for i in range(num_samples):
        record = db.read(i)
        expect = b"FAKE_JPEG_MAGIC" + b"sample-%04d" % i
        assert record == expect, f"第 {i} 条内容不一致: {record!r}"
    logger.info(f"[read] {num_samples} 条全部读出且内容一致  ✓")

    # ---- 4. 读 __len__ 元数据 key（str 类型的 idx）----
    meta = db.read("__len__")
    assert meta == str(num_samples).encode(), f"__len__ 值异常: {meta!r}"
    logger.info(f"[read] read('__len__') = {meta}  ✓")

    # ---- 5. 读不存在的 key：txn.get 返回 None（不抛异常）----
    missing = db.read(99999)
    assert missing is None, "不存在的 key 应返回 None"
    logger.info("[read] read(99999) = None  ✓")

    db.close()


def test_edge_cases(lmdb_dir: str):
    """边界行为测试（debug 打包问题时常用）。"""
    # ---- a. close 后继续 write：懒加载自动重开 ----
    db = Lmdb(lmdb_dir, writable=True)
    db.close()
    db.write(100, b"after-close-record")   # 不应报错
    db.write("__len__", b"24")
    db.close()
    logger.info("[edge] close 后 write 自动重开  ✓")

    db_ro = Lmdb(lmdb_dir, writable=False)
    assert db_ro.read(100) == b"after-close-record"
    assert len(db_ro) == 24
    db_ro.close()
    logger.info("[edge] 追加写入的数据可读  ✓")

    # ---- b. reset()：句柄重置后数据仍在 ----
    db_ro = Lmdb(lmdb_dir, writable=False)
    db_ro.reset()
    assert db_ro.read(0) is not None
    db_ro.close()
    logger.info("[edge] reset() 后句柄可用  ✓")

    # ---- c. get_keys() 慢路径：删掉 __len__ 元数据后走 cursor 遍历 ----
    raw = lmdb.open(lmdb_dir, readonly=False, lock=True, map_size=1024**4)
    with raw.begin(write=True) as txn:
        txn.delete(b"__len__")
    raw.close()

    db_ro = Lmdb(lmdb_dir, writable=False)
    keys = list(db_ro.get_keys())          # 慢路径，返回 bytes key
    assert b"0" in keys and b"100" in keys
    n_entries = len(db_ro)                 # 慢路径走 stat()["entries"]
    logger.info(
        f"[edge] 无 __len__ 时 cursor 慢路径: {len(keys)} 个 key, "
        f"len()={n_entries} (stat entries, 含全部 key)  ✓"
    )
    db_ro.close()

    # ---- d. pickle 跨进程传递（DataLoader worker 场景）----
    db_ro = Lmdb(lmdb_dir, writable=False)
    dumped = pickle.dumps(db_ro)
    db_ro2 = pickle.loads(dumped)
    assert db_ro2.read(0) is not None
    logger.info("[edge] pickle 序列化/反序列化后句柄独立可用  ✓")
    db_ro.close()
    db_ro2.close()


def check_real_lmdb(lmdb_dir: str, sample_count: int = 5):
    """对一个真实的打包 mdb 目录做体检：
    - 文件完整性（data.mdb / lock.mdb）
    - 总条数（__len__ 快路径 vs stat entries 慢路径，两者差值=元数据 key 数）
    - 抽样读取若干条，检查是否为 None（丢数据）及 JPEG magic
    """
    assert os.path.isdir(lmdb_dir), f"目录不存在: {lmdb_dir}"
    files = os.listdir(lmdb_dir)
    logger.info(f"[check] 目录内容: {files}")
    if "data.mdb" not in files:
        logger.warning("[check] ⚠ 缺少 data.mdb，可能是异常产物！")
    size_mb = os.path.getsize(os.path.join(lmdb_dir, "data.mdb")) / 1024**2
    logger.info(f"[check] data.mdb 大小: {size_mb:.1f} MB")

    db = Lmdb(lmdb_dir, writable=False)

    # __len__ 元数据
    meta = db.read("__len__")
    logger.info(f"[check] __len__ = {meta}")

    # stat 统计（含全部 key）
    if db.txn is None:
        db._create_txn()
    entries = db.txn.stat()["entries"]
    logger.info(f"[check] stat entries = {entries} "
                f"(与 __len__ 差值即元数据 key 个数)")

    keys = list(db.get_keys())
    logger.info(f"[check] 可读 key 数量: {len(keys)}, "
                f"前 5 个: {keys[:5]}, 后 5 个: {keys[-5:]}")

    # 抽样读取（首/中/尾）
    int_keys = sorted(int(k) for k in keys if str(k).isdigit())
    if int_keys:
        picks = [int_keys[0], int_keys[len(int_keys) // 2], int_keys[-1]]
        picks += int_keys[: max(0, sample_count - len(picks))]
        for k in picks:
            rec = db.read(k)
            if rec is None:
                logger.error(f"[check] ✗ key={k} 读取为 None，疑似丢数据！")
            else:
                is_jpeg = rec[:3] == b"\xff\xd8\xff"
                logger.info(
                    f"[check] key={k}: {len(rec)} bytes, "
                    f"JPEG magic: {is_jpeg}, head16: {rec[:16]!r}"
                )

    db.close()
    logger.info("[check] 完成")
