📝阶段结束写 stage_report.md学了什么 + 踩坑 ≥3 条 + 性能数据表。将来直接拼成 README。
⭐进阶选做可跳时间不够就跳过，不留恋，主线节点优先。

01

📅 阶段一：打牢 AI 异步网关与云原生基础

第 1-2 周 · N1-N19 · 19 个节点
核心目标：零基础亲手写出大模型网关四件套——异步、SSE 流式、跨块敏感词过滤、令牌桶限流——再用 Docker/K8s 部署上线。这些代码后面三个阶段全部复用。

▍第 1 周前半（Day 1-3）：从零摸到异步与流式

N1环境就绪 + 调试器就绪
概念铺垫venv（依赖为什么必须隔离）、requirements.txt（可复现性）、VS Code 断点调试（debug 是学习的主通道）
动手建 venv；装 fastapi/uvicorn/httpx/pydantic；pip freeze；git init + .vscode/launch.json
验收import 四件套无报错；F5 能断点单步进任意 py 脚本
N2事件循环心智模型本阶段地基
概念铺垫协程=可暂停/恢复的函数；事件循环=唯一的工人；task=被排队的协程。口诀：单线程单工人，谁 await 谁让出
动手exp_event_loop.py：两个 async 函数循环打印名字，中间 await asyncio.sleep(0) 主动让出，gather 并发
验收输出 A/B 交错而非 AAA BBB；threading.active_count() 证实全程 1 线程
N3同步 vs 异步体感实验
概念铺垫I/O 等待是什么；串行耗时=求和 vs 并发耗时=取最大
动手exp_async.py：三次 await sleep(1) 串行 vs gather 并发，perf_counter 计时
验收串行 ≈3s、并发 ≈1s；能不看书说出为什么
N4FastAPI Hello World（第一次接触 Web 框架）
概念铺垫uvicorn（监听端口收发字节）vs FastAPI（解析请求调用函数）的分工；路由；自动 /docs 文档
动手hello.py：GET / + GET /greet/{name}；uvicorn 启动；玩 /docs
验收curl 两接口通；/docs 在线调用成功；能回答"请求进来 uvicorn 和 FastAPI 各干什么"
N5最简流式接口（StreamingResponse 初体验）
概念铺垫普通响应 vs 流式响应（一次给全 vs 管道式一点点给）；异步生成器；TTFT 概念预告
动手main.py：GET /stream 异步生成器逐字 yield，包 StreamingResponse，media_type=text/plain
验收curl -N 肉眼见逐字到达；两终端同时 curl，两路流同时推进
N6SSE 协议标准化 + TTFT 实测
概念铺垫SSE 三要素（text/event-stream 头、data: ...\n\n 帧、连接保持）；两换行=帧边界；浏览器 EventSource；OpenAI 协议同构
动手写 sse_format()（ensure_ascii=False 中文坑）；/stream 改标准帧；对比"yield在前"vs"sleep在前"的首字延迟
验收浏览器 EventSource 收到逐帧事件；背出 OpenAI 流式三件套；TTFT 差异有实测数字

▍第 1 周后半（Day 4-7）：网关核心四件套之协议与过滤

N7Pydantic 校验 + OpenAI 兼容接口（非流式）
概念铺垫Pydantic=请求体的海关（错字段自动 422）；OpenAI chat 协议结构（messages/role/content/choices/usage）
动手ChatMessage/ChatRequest 模型；POST /v1/chat/completions 非流式分支，Mock 上游，响应对齐 OpenAI
验收官方 openai SDK 直连拿到回复；缺 messages 字段自动 422；能说出网关挡非法请求的意义
N8流式分支总装（上游异步流 → SSE 帧）
概念铺垫异步生成器做"上游"的抽象意义（生产者慢消费者快，管道解耦）；delta.role 首帧惯例
动手call_upstream_llm 异步生成器；stream=true 分支：首帧 role、中间帧 content、末帧 [DONE]
验收openai SDK stream=True 逐 token 收到；与非流式 TTFT 对比数字进日志
N9跨 chunk 敏感词过滤面试高频
概念铺垫问题本质：敏感词被拆到相邻两块（「垃圾」+「话」）；解法直觉：留尾巴——只放行确认安全的前缀，扣 max_len-1 个字符在缓冲区等下块拼接
动手①反面教材：拆块独立过滤亲眼看漏网；②实现 StreamFilter（push/flush+缓冲区）；③/demo/filter-demo 并排对比
验收naive 漏出、StreamFilter 被***替换、hit_count≥1；断点追一个词被拆两块的完整过程；能推导尾巴为何是 max_len-1
N10令牌桶限流器 + 中间件 + 压测
概念铺垫为什么必须限流（保护后端）；令牌桶 vs 固定窗口（允许突发、平均不超标）；中间件=所有请求的收费站；探针接口必须豁免（否则 K8s 误杀，事故高发）
动手手写 TokenBucket（rate/capacity/惰性补充/monotonic）；挂 @app.middleware；/stats 看板；load_test.py 30 并发
验收30 并发 → 恰好 10×200 + 20×429；/stats 计数吻合；429 带 Retry-After 头
N11第 1 周复盘
动手week1_report：坑 ≥3 条 + N6 TTFT 对比表 + N10 压测数字；commit 推送
验收每条坑都是"现象→原因→解决"，不是流水账

▍第 2 周前半（Day 8-10）：Docker 化（从"容器是什么"讲起）

N12Docker 概念 + 第一个镜像
概念铺垫容器 vs 虚拟机（共享内核只隔离进程视角）；镜像=分层只读模板；容器=运行实例；"我机器上是好的"→镜像把环境连代码一起冻住
动手Dockerfile（slim→pip→COPY→EXPOSE→CMD）；build；run；curl /healthz
验收容器内 /healthz、/stats 通；docker exec 确认代码和 Python 版本；镜像体积记录
N13K8s：集群与 Pod 概念 + 单 Pod 部署
概念铺垫为什么有 K8s（容器多了谁管调度/自愈/扩缩）；Master/Node；Pod=最小调度单位（一组共享网络存储的容器）；声明式=自愈的本质
动手kubectl run + port-forward；describe pod 看事件链 Pending→Pulling→Created→Started
验收port-forward 后 curl /healthz 通；能用自己的话讲 Pod；describe 输出能看懂大半
N14K8s：Deployment + 探针（声明式的第一次威力）
概念铺垫Deployment=Pod 的管理员（副本/自愈/滚动更新）；livenessProbe（失败→重启容器）；resources requests/limits
动手k8s_deployment.yaml：replicas=2 + livenessProbe(/healthz) + resources；kubectl apply
验收双副本 Running；delete pod 后自动重建（亲眼见 K8s 存在的意义）；logs 双副本都有；能串讲"探针为何免限流"

▍第 2 周后半（Day 11-14）：测试、收尾、验收

N15pytest 单测护城河⭐ 选做但强烈建议
动手StreamFilter/TokenBucket 单测（N9 对拍自动化）；故意改坏缓冲逻辑（keep→max_len-2）看测试能否抓出
验收pytest 全绿；"改坏→红→改回→绿"完整走一遍
N16架构图 + README 骨架
动手Mermaid 架构图；README 骨架（简介+图+数据占位）；week2_report
验收图中能看到限流在路由前、过滤在封帧前；README 有 N6/N10 真实数字
N17阶段一终验收三项全过才打 tag
①30 并发压测：10×200 + 20×429，/stats 吻合
②openai SDK 双模式直连成功
③K8s 双副本在线 + 杀 Pod 自愈演示
通过→ git tag stage-1-complete
N18预习衔接（0.5 天）

验收有 3 词清单——阶段二开课从你的 3 个词讲起
N19第 2 周复盘
动手week2_report（Docker/K8s 坑各 ≥2 条）+ 两周总 stage_report；commit 推送
